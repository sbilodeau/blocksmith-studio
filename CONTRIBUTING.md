# Contributing

Thanks for your interest in Blocksmith Studio. This file describes the conventions the codebase follows.

## Ground rules

- **English** for code, comments, file names, commits and documentation. The UI is translated (English and French).
- **No hard-coded UI text.** Every string shown to users goes through vue-i18n with keys in
  `src/shared/locales/en.json` and `fr.json`. ESLint (`@intlify/vue-i18n/no-raw-text`) fails on raw text, and a unit
  test checks that both locale files have the same keys and placeholders.
- **No Mojang assets in the repository.** Vanilla textures are read from the user's installation at runtime. Tests use
  synthetic fixtures generated by scripts.
- **Security first.** The renderer is sandboxed with context isolation and no Node.js access. New main-process
  features are exposed through typed, whitelisted IPC channels only (see [docs/architecture.md](docs/architecture.md)).

## Workflow

1. Create a branch from `main` (milestones use `m<N>-<name>`).
2. Make small, focused commits using conventional prefixes: `feat:`, `fix:`, `test:`, `docs:`, `ci:`, `chore:`, `refactor:`.
3. Before pushing, run:

   ```bash
   npm run lint && npm run typecheck && npm test && npm run test:e2e
   ```

4. Open a pull request. CI runs lint, type checks, tests on Windows/macOS/Linux, E2E on Windows and macOS, and a
   packaging smoke test.

## Tests

| Kind        | Location             | Runner                   | Notes                                                     |
| ----------- | -------------------- | ------------------------ | --------------------------------------------------------- |
| Unit        | `tests/unit/`        | Vitest (node)            | Pure logic: models, policies, calver, image ops           |
| Integration | `tests/integration/` | Vitest (node)            | Main services against temporary folders                   |
| Component   | `tests/component/`   | Vitest (happy-dom)       | Vue components and stores with a fake preload bridge      |
| E2E         | `tests/e2e/`         | Playwright (`_electron`) | Launches the real built app with an isolated profile      |
| AI eval     | `tests/ai-eval/`     | Vitest (node)            | Live model, skipped without `OLLAMA_API_KEY`              |
| Real jar    | `tests/real-jar/`    | Vitest (node)            | Your Minecraft jar, skipped without `BLOCKSMITH_REAL_JAR` |

AI code is tested without a network: the agent runtime against a scripted fake adapter
(`tests/unit/ai-agent-fakes.ts`), the Ollama adapter and the E2E specs against a local fake HTTP server
(`tests/fixtures/ai/server.ts`). Only `tests/ai-eval/` calls a real model (see
[docs/ai-evaluation.md](docs/ai-evaluation.md)).

Code that touches Electron APIs should keep its logic in pure functions (see `src/main/security-policy.ts`) or use
dependency injection (see `src/main/services/updater.ts`) so it can be unit-tested without Electron.

## Code style

Prettier (single quotes, no semicolons, 100 columns) and ESLint are enforced in CI. Run `npm run format` to fix
formatting. Markdown files are excluded from Prettier; keep tables aligned by hand and use "-" instead of em dashes.
